База опубликованной игры: `ce1f0206e39c4a743162b10a23ec74e322c938db` (`main` после иконки).
Ветка исправления: `cursor/title-jitter-qa-3e96`. Не влита и не выложена.
Телефон и сон: отдельный PR https://github.com/SergeyDuvakin/brake-it-anton/pull/5 , коммит `296a164f385571046316ca0539e848012bcc816c`. В эту ветку не входили и на сайт не публиковались.

Проверялось здесь: Node 22.23.4, Playwright 1.56.1, Chromium 141 (headless). WebKit в этой среде не установлен. Физических iPhone и Android не было. Playwright Chromium — не Safari и не Chrome на телефоне.

Запись владельца: ReplayKit, файл `user-jitter_f1c2.mov`, 5,49 с, поток 828×1792 с поворотом 90° (показ 1792×828), около 60 кадров/с. Это не замер FPS игры. Один автоповёрнутый кадр на 2-й секунде — титул «Brake It, Anton», «В урок», «Гараж». Покадровый поиск вертикального сдвига на уменьшенной копии (320×148 и сравнение с кадром 10) не дал непрерывного многопиксельного хода: после первого сэмпла сдвиг 0. Амплитуду на самом телефоне этот замер не доказывает.

Независимый разбор записи (не доказанная причина в коде): весь титульный холст, включая кнопки, едет вместе, в основном вертикально, относительно полей; внутри картинки детали не ползут друг относительно друга, кроме обычной живой анимации.

## 1. Аварии, безопасность, эксплуатация

Покупок, инвентаря, валюты и сетевого бэкенда нет. Это не баги, а отсутствие систем.

Сохранение — только `localStorage` ключ `brake-it-anton-save-v1`. Порча JSON не открывает уроки (`parseSave` в `js/storage.js`). Секретов в клиенте нет. Эксплуатации не найдено и не заявлялось.

Статус: подтверждённых дыр нет. Непроверенный риск: подмена `localStorage` на своём устройстве меняет только локальный прогресс. Серьёзность: Низкая.

## 2. Игра, состояние, время, крайние случаи

Интегратор шагает по 1/60 с, кадр браузера режется до 0,1 с (`frame` в `js/game.js`). Это не источник синхронного сдвига всего титула.

`sim.shake` затухает (`sim.shake - dt * 18`) и на титуле не используется. Ударная тряска есть только в `drawPlay`, и только пока `sim.shake > 0`.

Повтор урока и зазор перед пешеходом на `main` уже опубликованы раньше. Эта ветка их не откатывает.

## 3. Интерфейс, мобильный ввод, Safari и Android Chrome

Один и тот же CSS служил и Safari, и Chrome. Отдельного Safari-only обхода, который ломает Chromium, не добавлялось.

`viewport-fit=cover` уже был. Добавлен стандартный `interactive-widget=overlays-content`. Отступы `env(safe-area-inset-*)` на `#wrap` одинаково понимают вырез iPhone и Android. Это не проверка реального выреза.

Ввод педали по-прежнему один указатель: чужой `pointerup` её не отпускает. Это уже было на `main`. Два пальца на Android и iPhone этой правкой не переписывались.

Портрет по-прежнему просит повернуть телефон. Вертикальной игры нет.

## 4. Производительность

Замеров FPS и утечек памяти нет. Их нет в отчёте как фактов.

Холст остаётся 1600×900 в растре. Отдельный backing store под DPR не делался: это резкость, не сдвиг всего кадра, и он меняет попадание по кнопкам. Серьёзность как непроверенный риск: Низкая.

## 5. Картинка и анимация

### 5.1. Весь титул едет вместе. Серьёзность: Средняя. Статус: исправлено в ветке, не опубликовано.

Описание. На титуле кнопки и дорога не сдвигаются одним `ctx.translate`. Живая анимация (`boil`) двигает только отдельные спрайты. Единственный способ сдвинуть и «В урок», и дорогу вместе — сдвинуть сам элемент `canvas` в странице.

Было, `style.css` на `ce1f0206e39c4a743162b10a23ec74e322c938db`:

```css
canvas {
  touch-action: none;
  background: #F6ECD6;
  width: min(100vw, calc(100vh * 16 / 9));
  height: min(100vh, calc(100vw * 9 / 16));
  max-width: 100vw;
  max-height: 100vh;
}
```

`100vh` в Safari и в Chrome Android меняется вместе с панелью браузера. Холст был по центру flex-контейнера. Если высота, от которой считается холст, меняется, а внешний кадр телефона нет, холст и прыгает, и меняет размер. Модель старой формулы: при внешней высоте 430 и скачке используемой высоты 430 → 414 вертикальный центр уезжает на 8 пикселей. Это проверка формулы в `test/sim.test.js`, не замер с iPhone.

В `drawTitle` (`js/draw.js`) нет общего сдвига на мир и кнопки сразу. Тряска `if (mag) ctx.translate(...)` есть только в `drawPlay` и только при `sim.shake > 0`. На титуле её нет.

Стало. Размер считается один раз для Safari и Chrome, целыми пикселями, и не меняется, пока высота или ширина не ушли больше чем на 2 пикселя.

`js/viewport.js` целиком:

```javascript
export function frameSize(viewW, viewH, logicalW = 1600, logicalH = 900) {
  const availW = Math.max(1, Math.floor(viewW));
  const availH = Math.max(1, Math.floor(viewH));
  let width = availW;
  let height = Math.floor((width * logicalH) / logicalW);
  if (height > availH || height < 1) {
    height = availH;
    width = Math.max(1, Math.floor((height * logicalW) / logicalH));
  }
  return { width, height };
}

export function stableFrame(previous, viewW, viewH, slack = 2) {
  const next = frameSize(viewW, viewH);
  if (!previous) return next;
  if (Math.abs(next.width - previous.width) <= slack && Math.abs(next.height - previous.height) <= slack) {
    return previous;
  }
  return next;
}
```

`fitCanvas` в `js/game.js`:

```javascript
function fitCanvas() {
  const wrap = document.getElementById("wrap");
  const box = window.visualViewport;
  const width = wrap && wrap.clientWidth > 0 ? wrap.clientWidth : box?.width || window.innerWidth;
  const height = wrap && wrap.clientHeight > 0 ? wrap.clientHeight : box?.height || window.innerHeight;
  const next = stableFrame(frameSize, width, height);
  if (frameSize && next.width === frameSize.width && next.height === frameSize.height) return;
  frameSize = next;
  canvas.style.width = `${next.width}px`;
  canvas.style.height = `${next.height}px`;
}
```

CSS сначала оставляет старый `vh` как запас, затем `svh`: маленькая вьюпорт-высота не следит за уезжающей панелью. Скрипт поверх ставит целые пиксели. `visualViewport` есть и в Safari, и в Chrome.

Регрессия. Юнит: скачок 390↔391 и 390↔389 не меняет размер; скачок до 360 меняет. Playwright Chromium: 844×390, 915×412 (ширина уровня Pixel) и 800×360. После серии высот ±1 и ±2 верх, левый край и высота холста остаются в пределах 1,5 пикселя, ширина и высота целые, отношение сторон около 16:9.

Не доказано этой правкой: что именно эта амплитуда была на том iPhone. Запись грубым поиском непрерывный многопиксельный ход не зафиксировала.

### 5.2. Кипение статичных декораций. Серьёзность: Низкая. Статус: не менялось.

`boil` раз в 110 мс двигает крону дерева на 7 пикселей и дома на 1,2. Кнопки титула при этом стоят. Это не тот симптом, где едет весь интерфейс. Менять рисунок всех домов в этом патче не стал.

### 5.3. Тряска от удара. Серьёзность: не дефект. Статус: оставлено.

Включается настройкой и только на время `sim.shake`. На титуле не рисуется.
